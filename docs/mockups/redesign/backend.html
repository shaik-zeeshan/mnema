Block a tool on first request

rustdecision

Decided 2026-10-10: add block_identity, a second row-creating writer for standing rejections only. The CLI access request has a Block button; block_client only flips rows that exist (brokered_access.rs:2216-2221), and Deny persists nothing (in-memory channel reply only), so an unknown tool can re-open the window every command. Build: in brokered_access.rs, under one with_grants_lock — row exists → flip blocked + blocked_at_unix_ms only; no row → create {id: random, scope: LAST_DAY, blocked: true, blocked_at: now, last_used: 0}; never touch an existing scope or id. Plus a channel command that answers the pending request with blocked, its registration, and the button. Grants live in broker-grants.json — no migration.

Why this doesn't break ADR 0059: the ADR promises one row per tool, id preserved on widen (opaque ids are signed against it), and a rejection that is standing. A blocked-first row keeps all three — a blocked row is never "active" and never issues opaque ids, so the id-preservation reason behind "upsert is the only row-creating writer" is moot for it. Reword CLAUDE.md / AGENTS.md line 27 + the code comment to name both writers; one-line ADR amendment. Follow-ons in the same change: Enable on a never-granted row (last_used == 0) deletes it so the next request re-asks instead of silently granting last-day access (today's Enable dialog says "…able to read … again"); --no-prompt reports "blocked" instead of "approval required, retryable".
