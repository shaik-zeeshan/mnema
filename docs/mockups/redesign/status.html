Decision

Where does developer info live?

Two different questions: “what is Mnema doing right now?” and “why is this broken?”. Three homes were considered for the second one.

developer main window
A · Small separate windowrecommended

A status popover in the main window for everyone, plus a small Developer window for diagnosis.

  • Sits beside the app while you reproduce a bug.
  • Never takes room from the screen you are testing.
  • One more window to open, so it needs ⌘D and a button in Settings.
developer page
B · A Settings page

Developer becomes one more section in Settings.

  • Easy to find, nothing new to learn.
  • Settings takes over the main window, so you can’t watch it while you use the app.
  • Live numbers don’t belong among preferences.
drawer surface under test
C · Side drawer

A panel that slides in from the right of the main window.

  • Always one shortcut away, no extra window.
  • Crowds the very surface you are testing.
  • Repeats what the status bar already says.

Two audiences, two homes. Everyone gets the status popover: what Mnema is doing now, one click from the status bar, no setting needed. Developers get the Developer window for diagnosis, after turning on developer options. The bell keeps events, things that happened; the popover shows now, so the two never repeat a row.
