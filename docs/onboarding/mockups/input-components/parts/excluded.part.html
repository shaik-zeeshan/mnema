How the icon sits in a sentence
  • A glyph on the baseline, not a tile. A bordered 20 px square turns each name into a chip and the sentence back into a list. The mark here is a stroke drawing masked to currentColor, sized 1em and dropped -.16em so its optical centre lands on the cap-height centre of the words around it.
  • The line box never grows. At line-height: 2.05 the glyph's margin box (1em) is smaller than the strut, so adding icons changes no line height and no wrap point — the sentence occupies exactly the rows it did without them.
  • Glyph + name is one unbreakable word (white-space: nowrap), so a break can only ever land on a comma. “Keychain Access” never splits, and an icon is never orphaned at the end of a line.
  • Punctuation still hugs. The buttons carry vertical padding only; the commas and the “or” are plain text between them, so nothing gaps before a comma.
  • The “this is clickable” underline stops at the word. Drawn on the name span, not on the button, so it never runs under the icon — at eight apps a full-width underline merges into one ragged rule and the line starts reading as a table.
  • Colour carries the category, not a background. Password apps read one tint, messaging another — visible at a glance, invisible as decoration. Struck names take their glyph down to --app-text-faint with the strike drawn through it.
  • The waiting state is the absent icon. An app you haven't installed has no icon to show, so it shows a dashed empty square — the “we don't have this yet” signal is the same object that would carry the icon, not an extra badge.
  • Where it stops working — measured, not guessed. Grown one app at a time through the ＋ chip at both 640 px and 560 px: 3–8 apps is two lines and still reads as a sentence (icons act as the separators, so the eye finds each name without the commas doing all the work). 9–11 is three lines and it has quietly become a list wearing sentence punctuation. 12+ is four lines and should not be a sentence at all. Onboarding seeds three and nobody adds five more on step 3, so the shipped range is inside the comfortable half — but if the seeded catalog ever grows past eight, this control has to become the chip list, not get a smaller font. Settings keeps the full editor for the power user's twenty either way.
Implementation
  • Replaces apps/desktop/src/routes/onboarding/screens/CaptureStorageScreen.svelte:304‑327 — the “{n} apps — Edit ▸” summary row plus the {#if editingExclusions} block that mounts AppPrivacyExclusion inline.
  • Deletes let editingExclusions = $state(false) (same file, line 172) and its three reads, the Edit ▸ / Done button, the .editor wrapper and its CSS, and the comboboxListId="capture-storage-privacy-app-list" prop. AppPrivacyExclusion.svelte itself stays — Settings still needs the full editor. excludedSummary (line 189, “first three then …”) goes too: the sentence prints every name.
  • Striking a name is not a new concept — it is the existing set_privacy_excluded_app_enabled(sourceId, enabled) command (app-privacy-exclusion.svelte.ts:178). The entry stays in PrivacySettings.excluded_apps with enabled:false, which is why a struck name can stay in place and never reflow the sentence. Nothing is removed from onboarding, so remove_privacy_excluded_app is not wired here at all.
  • Real icons, not these glyphs. The app already resolves them: resolveAppIcons() → iconPathForBundleId() → convertFileSrc(), with appIconFallback()'s letter monogram when a path is missing. The sentence reuses that pipeline at 1em; the CSS masks below exist only because this mockup may make no external request.
  • Backend change — “add an app you haven't installed yet.” Today's combobox offers installed apps only (PrivacyAppCandidateDto, enumerated from the running system), and every consumer keys off bundle_id: uniqueBundleIds() (app-privacy-exclusion.ts:86) silently drops an entry whose bundle id is empty, so a name-only rule stored today protects nothing and says nothing. ExcludedAppEntry {id, enabled, bundle_id, display_name} can already hold it, so the change is (a) accept a rule with an empty bundle_id and a typed display_name, (b) resolve it — on app-list refresh or first sighting — by display name, filling the bundle id in place, and (c) keep the unresolved rows out of the screen filter and the tap exclude list until they resolve. Until that lands, the dashed “when you install it” state is a promise the backend does not keep.
  • The audio claim stays qualified. An excluded app is cut from the screen recording and from the system-audio tap only while Settings → Privacy → filter system audio is on: system_audio_privacy_excluded_bundle_ids() (apps/desktop/src-tauri/src/native_capture/privacy.rs:89) withholds the whole privacy list when that toggle is off, leaving the tap excluding Mnema's own process and nothing else. The note line never says “and system audio” without “while that filter is on”.
  • Known ceiling: nothing can be deleted from the sentence, only struck — so a typo'd “add” leaves a struck row behind until Settings removes it. Worth the trade: one rule, one command, and what the app chose for you can never be made invisible.
