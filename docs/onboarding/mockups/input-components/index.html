Implementation

Replaces three rows with one line. apps/desktop/src/routes/onboarding/screens/CaptureStorageScreen.svelte — the rate slider (~:243-263, the .lad-wrap range + readout), the storage field (~:273, path + Change + free-space note) and the retention segmented group (~:287-296) all collapse into this sentence. The screen's heading "Four things to settle." becomes one sentence plus the video-quality row. It also deletes the duplicate surfaces on ChangeSettingsScreen.svelte — :401 <RetentionPicker> and :416 the capture-rate <Select> — because a user who has already read the sentence should not meet the same two settings again in a different control (the standing "same setting, different control" complaint).

Backend: nothing new. probe_storage_path (src-tauri/src/managed_storage_layout.rs) already returns exists / writable / free_bytes, and null free space already means "couldn't measure", not "zero". The folder token calls the existing @tauri-apps/plugin-dialog open({ directory: true }); the <dialog> here only simulates it for the mockup.

One gate change. apps/desktop/src/lib/onboarding/gates.ts:58 compares freeBytes < requiredBytes and stops there — the download work-list only. Drive "a day doesn't fit" above: the downloads fit, so the shipped gate passes, and the user is sent into a first session with no room for a single day of capture. The gate needs a second term — freeBytes - requiredBytes - LOW_DISK_RESERVE < dailyBytes(intervalS) — which means gates.ts has to take the capture interval it does not take today. The same dailyBytes() feeds the sentence and the gate, so the blocking reason and the printed consequence can never disagree.

The Semantic Search escape does not actually rescue that volume, and the mockup shows it honestly: dropping nomic (548 MB) clears today's gate on the SD card, and the volume still has nowhere to record. That is the argument for the second gate term in one click.

Ghost windows. The number of faint neighbours is per token, because the ladders are not the same length. Retention has four values, so it prints all of them — the whole choice set is on screen and "keep everything" can never read as a statement instead of one of four. Rate has eleven, so it prints a five-wide window centred on the chosen stop and clamped at the ends, which keeps exactly four ghosts at every position (no ragged row at 0.1 s or 60 s) and puts a ±2 jump one click away. The folder has two states, so it prints one ghost — ~/.mnema — and only while you are away from it: undoing a folder change is clicking a word. That one rides at the very end of the sentence rather than beside the token, so the full stop still lands on the folder and a broken sentence gets to finish its clause before the undo appears.

Keyboard parity. Ghosts are aria-hidden and out of the tab order — three extra tab stops per token is the wrong trade — but every value a ghost can reach is reachable from the token itself: Tab moves between tokens, ← → step, Page↑ / Page↓ jump ±2 (the outer ghost), Home / End go to the ends of the ladder, Enter on the folder opens the picker. The token is a role="spinbutton" carrying aria-valuetext, so a screen reader hears the word, not the index. Clicking the word steps forward and wraps; arrows clamp.

Retention vs the sentence. Round 2 flagged that the sentence's best clause — "12 GB held at any time" — is absent in the default case, because never has no ceiling. Solved by never printing a ceiling at all: the plan line always reads rate · horizon, and the horizon is a first-year projection while retention is never ("about 148 GB in the first year, and it keeps going") and a steady ceiling once it is not ("12 GB held, then it stops growing"). Both are one computed number in the same position that moves when you move the rate, so the default is the strongest reading rather than a hole, and retention's job becomes legible: it trades a growing projection for a fixed ceiling. Hover or click a retention ghost to see the swap before committing.

How the icon sits in a sentence
  • A glyph on the baseline, not a tile. A bordered 20 px square turns each name into a chip and the sentence back into a list. The mark here is a stroke drawing masked to currentColor, sized 1em and dropped -.16em so its optical centre lands on the cap-height centre of the words around it.
  • The line box never grows. At line-height: 2.05 the glyph's margin box (1em) is smaller than the strut, so adding icons changes no line height and no wrap point — the sentence occupies exactly the rows it did without them.
  • Glyph + name is one unbreakable word (white-space: nowrap), so a break can only ever land on a comma. “Keychain Access” never splits, and an icon is never orphaned at the end of a line.
  • Punctuation still hugs. The buttons carry vertical padding only; the commas and the “or” are plain text between them, so nothing gaps before a comma.
  • The “this is clickable” underline stops at the word. Drawn on the name span, not on the button, so it never runs under the icon — at eight apps a full-width underline merges into one ragged rule and the line starts reading as a table.
  • Colour carries the category, not a background. Password apps read one tint, messaging another — visible at a glance, invisible as decoration. Struck names take their glyph down to --app-text-faint with the strike drawn through it.
  • The waiting state is the absent icon. An app you haven't installed has no icon to show, so it shows a dashed empty square — the “we don't have this yet” signal is the same object that would carry the icon, not an extra badge.
  • Where it stops working — measured, not guessed. Grown one app at a time through the ＋ chip at both 640 px and 560 px: 3–8 apps is two lines and still reads as a sentence (icons act as the separators, so the eye finds each name without the commas doing all the work). 9–11 is three lines and it has quietly become a list wearing sentence punctuation. 12+ is four lines and should not be a sentence at all. Onboarding seeds three and nobody adds five more on step 3, so the shipped range is inside the comfortable half — but if the seeded catalog ever grows past eight, this control has to become the chip list, not get a smaller font. Settings keeps the full editor for the power user's twenty either way.

Feature switches

Eight on/off rows that decide what Mnema records, what it understands, and what it downloads before it can do either — drawn as the dependency graph they actually are, so a cascade is visible before you commit it.

What Mnema will do Indented rows need the row above them.

Drive it

Hover or keyboard-focus any row to see what flipping it would take with it: the branch goes dashed, every row that would move is tagged goes off, and the same sentence is announced on aria-live. Space/Enter commits. Nothing here is hardcoded — the rows are rendered from the dependency model below.

Implementation notes
  • Replaces the eight <Switch> rows in apps/desktop/src/routes/onboarding/screens/ChangeSettingsScreen.svelte: Screen capture :236, Microphone :252, System audio :271, Read on-screen text :295, Transcription :330, Who's speaking :347, Semantic Search :380, AI features :448. The rows keep living in three different <section class="sec"> blocks today (Capture sources / Processing / AI features) — this component pulls the eight into one ordered chain so a parent and its children are never in different scroll positions. Model pickers and provider Segmenteds stay where they are; only the on/off column moves.
  • Deletes the two pre-emptive hint strings that are the only cascade copy in the app today: "Turning this off also turns off transcription and who's speaking" (:249) and "Needs transcription on." (:343). Both said the rule; neither said what just happened. The chain shows the rule structurally and the preview says what will happen, per flip.
  • Needs two new exports from apps/desktop/src/lib/onboarding/feature-rules.ts. It exports normalizeFeatures, featureLockReason, systemAudioNeedsRequest, featureToggleDisabled and applyToggle — and not cascadeOf or preview. Both are pure additions over the existing applyToggle (which already returns a new state and never mutates its input): cascadeOf(before, after, touched) diffs the two states, and preview(state, id) is applyToggle plus that diff. No backend change, no Tauri command, no new state in the flow. The one flow change: onboarding-flow.svelte.ts:153 toggleFeature must keep the pre-toggle state so the undo chip has a snapshot.
  • One new lock case. Today featureLockReason only locks microphone (permission) and speakerSeparation (needs transcription). Turning Transcription on with no audio source is currently a silent no-op — applyToggle sets it true and normalizeFeatures immediately unsets it, so the switch bounces back with no explanation. This component adds the missing case ("Needs an audio source on"), which is one line and makes the already-true rule speakable.
  • Locked rows show the fix, not a dead switch. Microphone renders Grant Microphone where its switch was — the lock is a permission the user cannot resolve from any visible row. Rows locked by a parent (Who's speaking, Transcription) render a ghost button that flips that parent instead. Note the honest asymmetry: turning Transcription back on does not restore Who's speaking (applyToggle only re-forces both from an audio source, by design — the user may have turned it off deliberately). The undo chip is the remedy for that, not a second cascade.
  • System audio never locks (ADR 0052 — the grant is unqueryable, so a lock would be a gate that can never open). If systemAudioNeedsRequest is true the row carries the annotation, never a disabled control.
  • Numbers. Download bytes are the manifest figures (Whisper base 147,951,465 · speakrs 419,482,724 · nomic ≈548,000,000 — any total containing nomic reads "about"). Disk decomposes the one measured anchor: 270 MB/day at a snapshot every 3 s, with both audio sources on and no embeddings. Semantic Search sits on top of the 270 (one 768-dim f32 vector per frame-document), because the measured machine shipped none. The console.assert block reproduces the 270 exactly and fails loudly if any constant drifts.
  • a11y. Each switch is a real role="switch" button with aria-checked, keyboard-operable with Space/Enter, and described by its own row copy via aria-describedby — a screen reader is told which parent a row hangs off in words, never by the indentation. The preview and every commit are announced in the polite live region, so a cascade is never a purely visual event. Focus rings are var(--app-ring); prefers-reduced-motion drops the transitions and keeps every state change.

Component

AI provider setup

Whether AI features run at all, whether your words leave this Mac, and which model answers — decided by a connection that has to prove itself before it counts.

States you can drive

Nothing here talks to a network. A deterministic fake table decides reachability: a key containing reject is refused 401, a host that is not in the table refuses the connection, and the scan only answers on ports something is actually listening on.

What this replaces

  • ChangeSettingsScreen.svelte:448 — the bare AI switch. Becomes the outcome of connecting, not the entry point: nothing is asked until the user answers "later" or "now".
  • :463–471 / :483–492 — the two rows of + kind buttons (one per local kind, one per cloud kind). Deleted. A single grouped selector plus Scan this Mac replaces eight buttons that all did the same thing: append an empty, unverified row.
  • :516 base URL, :525/:539 key field + Save key — the Save button goes. Reaching the provider is the save: the key is sent, the model list comes back, and the list is the receipt. A key that cannot list models never becomes a saved provider.
  • :553 the local endpoint field — demoted to the fallback under the scan. Typing a port is for the engine on another machine, not for the one already running here.
  • :570 ModelPickerMenu — the merged menu stays as the readout, but the chips inside each live card are the selection surface, so a model that was not in the last live listing is not offerable.

Backend change this design requires

This component's readiness rule is stricter than production: a default model counts only if its provider verified live and that live listing still contains that exact model id. Today the app can finish onboarding with AI enabled and no working model, which lands straight on the known bug where a job against an absent model dies in about six minutes and is never retried. Four call sites:

  • onboarding-ai.svelte.ts:144–157 — aiConfigMissing treats a cloud provider as configured once a string was written to the keychain. No validity check at all, and non-cloud kinds get no endpoint check either. Needs to read a verification result, not key presence.
  • :189–193 — aiUnverifiedNote ("Key saved but unverified") already knows the truth and is deliberately only a hint. Promote it: unverified must fail aiConfigReady, not annotate it.
  • ChangeSettingsScreen.svelte:182 — aiBlocked reads that same soft readiness, so the one hard gate in onboarding is gated on an untested key.
  • :188–192 — the $effect auto-enables the feature on the false→true readiness transition. Auto-enabling on an unverified provider is how the user ends up with AI on and nothing behind it. Keep the auto-enable, but fire it off verified readiness only.
  • syncFromSettings (:114–124) — restores a persisted default model without checking it still exists in any live pool. A model the provider dropped (renamed, deprecated, unpulled locally) survives a reload as a valid-looking default. It must be re-validated against the fetched pool and cleared with a visible reason when it is gone.

Concretely: one verify_ai_provider(id) → { models: [], latency_ms } command that lists models with the key the vault holds, called on connect and on Test; readiness derived from its result plus a membership check of the chosen model id. The frontend never needs the key back.

Secret handling

The key field is type="password", autocomplete="off", data-1p-ignore, data-lpignore, and has no value attribute — the demo buttons assign the input property. The string is read once, sent, and the field is cleared; state keeps a boolean, never the text. Nothing renders it, so it never reaches markup, an aria-label, a title, or a URL.
