(a) Thesis

A transcript is a document a person reads, not a log they scan. This direction optimises ruthlessly for comprehension of the words: a generous measure, real paragraph rhythm, larger body type, no columns of metadata competing with the sentence. Identity repair still exists — it has to, because unknown and wrong are the common states — but it lives in a quiet left gutter and a slide-over, and it is never allowed to interrupt reading.

(b) Callouts

  1. Escape the 50vh drawer. The peek state (frame 4) survives as an entry point from the timeline — it answers "what is this segment" in two paragraphs. Reading happens in the expanded surface (frame 1), which is where every other decision below becomes affordable. Fifty vertical percent of a fixed drawer cannot host a 4-minute conversation and a generous measure at the same time; something had to give and it was the drawer.
  2. 15px / 1.72 / ~58ch — the one house-style break, taken deliberately. Mnema's 12px monospace norm is tuned for dense control surfaces: settings rows, meta strips, timeline chrome. Long-form prose is a different job. At 12px with a 100ch measure the eye loses its place on line return; at 15px with a 58ch measure it doesn't. The typeface stays monospace and every other surface keeps 12px — the break is scoped to .para only, and the gutter, header and transport all remain at 10–11px house scale, which is what makes the prose read as the figure and everything else as ground.
  3. P3 karaoke, and it is load-bearing. The current word is highlighted as playback advances; clicking any word seeks there (press play in frame 1). This is the strongest available cue that a transcript is media rather than a text file — and it is what pays for callout 4, because once the highlight tracks the audio, a timestamp column has nothing left to do. Degradation (frame 3): when a provider emits no words[], the highlight snaps to the whole paragraph. Same mechanic, coarser unit, no dead feature and no empty column.
  4. P4 timestamps default OFF, one toggle away. YouTube's move. With them off the transcript is clean, copyable prose — select-all gives you something you can paste into a doc without stripping [00:01:14] out of every line. The toggle sits in the header and persists; frame 2 shows the on state, where the time takes a second line in the gutter rather than a third column, so turning it on never reflows the measure.
  5. Speaker identity as a quiet right-aligned gutter, dual-encoded. Name plus a 12px marker that carries both a colour and a shape (circle / square / triangle / diamond) — Google Recorder's trick, and the reason the transcript still parses in greyscale, at low contrast, or with any form of colour blindness. Colour is derived from clusterId; there is no speaker-colour field in the schema and this mockup does not pretend otherwise. The gutter is right-aligned so the ragged names sit flush against the prose block and form a clean edge instead of a second ragged column.
  6. Unknown is a state, not an error. "Unknown speaker · 2" is set in normal weight and normal muted colour with a hollow dashed marker — visibly not yet named, never red, never a warning, never an exclamation mark. Only two shipped products (Happy Scribe, Zoom) treat unknown as legitimate; in always-on capture it is the majority state, so treating it as a failure would mean a permanently alarming UI. The one affordance is a whispered "name this voice" under the name on hover.
  7. Follow mode done right. Auto-scroll keeps the current word centred. Any manual scroll immediately detaches it — no fighting, no snapping back — and a "↓ jump to playhead" pill fades in above the transport. Click it or press Esc to re-attach. Descript's fix for the Premiere / MS Stream failure mode. (Scroll frame 1 while it is playing to see the detach.)
  8. Repair: hover → whisper → slide-over. Hovering a speaker name reveals a single ⋯. It opens a slide-over (frame 5) pinned to the right edge — never a modal, never a centred popover over the text, because the whole point of a repair surface is that you can keep reading the lines you are trying to attribute. Inside: name, an explicit scope segmented control defaulting to cluster-wide (P5 — Descript's silent global relabel is its single most-complained-about behaviour; the fix is not a different default, it is a visible one), link-to-person, and the suggested merge (P6) with a "play 8s of each" button, which is Buzz's audio-first identification — you should identify a voice by hearing it, not by reading a transcript of it. Every commit fires an undo toast naming the blast radius: "renamed 11 turns · Undo".
  9. Every non-happy path is drawn (frame 6). The five frames above are the transcript working. Frame 6 is the other eleven status values the drawer can reach: loading (a skeleton in the shape of the content, not a spinner), processing with the stage it is on, no-speech as a legitimate outcome rather than an error, a partial failure that says which half survived and offers the half that works, and never-run with the one-click way out. Each carries a status pill in the header that is a role="status" aria-live="polite" region, because these change without the user doing anything.
  10. Dismiss and reject are different actions and now look it. The inline ✕ on a suggestion is a soft dismiss: it hides the row and writes nothing. The destructive twin — "Not this person", which persists a rejection embedding that suppresses that person for every future recording — lives in the slide-over, styled danger, with its permanence spelled out underneath. These were previously the same 10px glyph.

(d) New data required

None. This direction adds no fields. Two things it uses are not consumed by the drawer today but require no schema change: TranscriptionStructuredPayload.words[], which already exists in the payload, and the waveform peaks, which are computed in Rust from the audio itself using a decoder this repo already ships — see (h). Nothing is drawn that the schema cannot supply: no avatars, no per-turn ASR confidence in the default view, no summaries.

(e) Explicitly rejected

  • Dense log formatting. No time | speaker | text rows, no zebra striping, no fixed-width timestamp column. That layout optimises for locating a moment; this surface optimises for understanding a conversation, and you cannot have both as the default.
  • Always-on timestamps. They are metadata rendered at the same visual priority as speech, they poison copy-paste, and karaoke already answers "where am I".
  • P7 confidence-as-texture in the default view. Sonix's opacity heatmap is genuinely good in a review pass and genuinely corrosive as a default: a page of half-faded words reads as "this transcript is unreliable" before you have read a sentence of it. It belongs behind a "review low-confidence words" mode, which this direction does not draw.
  • Analytics. No talk-time bars, no speaker pie chart, no words-per-minute. Derivable, cheap, and completely orthogonal to reading what was said.
  • P8 summary-first. Deliberately dropped despite being near-universal for always-on capture. A summary above the transcript makes the transcript the appendix; this direction's entire wager is the opposite.
  • P11 filter-as-highlight / P12 chapter rail. Both are real gaps — see the tradeoff below — but both add a second navigation layer competing with the prose. If one returns, it should be find-in-page (P11), not a rail.

(f) The honest tradeoff — what this is worse at than today's drawer

  • Skimming for a moment is slower. Timestamps off by default plus generous leading means "find the bit around 3 minutes" is a scroll-and-scan, not a glance down a column. One toggle fixes it, but the default costs you.
  • Vertical throughput drops hard. 15px/1.72 with 24px between turns shows maybe a third of the turns per screen that the current 12px drawer does. A rapid four-way back-and-forth becomes a lot of scrolling — the classic P1 failure, and this direction leans further into it than most.
  • It gives up the timeline. The current drawer is non-modal (aria-modal="false") and you can click another bar behind it to swap segments. An expanded reader covers that. The peek state is the mitigation, but the expanded state genuinely loses a real capability, and someone triaging a whole afternoon will feel it.
  • Bulk repair is slower than it could be. One speaker at a time through a slide-over. There is no roster view, no MacWhisper-style hover-and-press-1 reassignment (that interaction is arguably the highest-leverage one in the entire competitive set, and it is incompatible with a surface whose hover state is reserved for reading). Fixing ten mislabelled clusters is ten trips.
  • Still no search and no coarse navigation. Neither exists today either, so it is not a regression — but a reading surface makes the absence of find-in-page more conspicuous, not less.

(h) The waveform — real peaks, computed, never stored

Mnema stores no waveform data. AudioWaveform.svelte is a decorative static 9-bar SVG with a widthPercent prop, and SpeakerAnalysisProvenance.audioPeak is a single scalar for an entire segment. A scrubber that drew either of those would be an illustration of a waveform, not a waveform — and a fake one is worse than none, because users navigate by its shape.

So the peaks are computed in Rust, from a decoder this repo already ships, and handed to the drawer as a Vec<f32>. No new crate, no new dependency, no schema change. This was checked against how Cap (cap.so) does it — see the note at the end.

StepDetail
DecodeReuse macos_audio_decode.rs — it already exists twice, in crates/speaker-analysis and crates/audio-transcription, as near-duplicates. av::AudioFile::open_read_common_format(&url, av::AudioCommonFormat::PcmF32, false) via cidre, with an AVAssetReader → temp-WAV fallback. AVFoundation is hardware-accelerated, handles the AAC-LC that capture-writers writes, and adds no C toolchain. Promoting one copy to a shared home is a prerequisite worth doing anyway.
Reducemax(|s|) per bucket, accumulated while the decoder's buffers stream past — 150 buckets over a 5-minute segment is one per ~2 s (~96k samples at 48 kHz). About fifteen lines.
Never hold the PCMThe whole point of folding the reduction into the decode loop: peak RSS is one buffer, not the file. A 5-minute segment fully resident at 48 kHz mono f32 is ~57 MB; the surviving output is 150 floats — 600 bytes. This repo has been burned by audio-path memory before, so this is the load-bearing constraint, not an optimisation.
DeliverA #[tauri::command] returning Vec<f32>. No sidecar file, no disk cache, no event stream. If the decode ever feels slow, cache the 150 floats as a column on the audio_segments row that already exists — never as a .dat on disk.
DegradeDecode failure returns an empty vec and the scrubber falls back to the plain progress bar the drawer has today. No error state, no empty box — playback surfaces the real problem.

What Cap does, and where this deliberately differs. Cap computes peaks in Rust too (apps/desktop/src-tauri/src/audio.rs, 30 lines) and ships them over a Tauri command as Vec<Vec<f32>> — same shape as above. Two differences, both deliberate:

  • Cap decodes with ffmpeg-next (their own fork, pinned by git rev), which means a C FFmpeg link, pkg-config at build time, and LGPL obligations for a distributed binary. Mnema does not need it: the input codec is AAC-LC that Mnema itself wrote, and AVFoundation decodes it natively. (If this ever has to leave macOS, the answer is symphonia 0.6 with features = ["aac", "isomp4"] — pure Rust, MPL-2.0, no C toolchain. Not ffmpeg-next.)
  • Cap keeps the entire decoded track resident in an Arc<AudioData> for the editor session, so peaks are a free by-product of audio it needs anyway for playback and export. Mnema has no such need, so it must not copy that part — hence reducing inside the decode loop and dropping the buffer.
  • Cap buckets at a fixed 10 values per second and uses mean of |sample|, converted to dBFS with silence floored at −60. Mean-abs over 100 ms visually flattens speech transients; for a 150-bar scrubber, max(|s|) per bucket costs the same and looks better. Skip the dBFS conversion unless the bars read as too spiky.

There is no usable off-the-shelf peaks crate. waveform (2017) is abandoned on gtk 0.1; audio-waveform has double-digit downloads and is days old; BBC's audiowaveform is a GPLv3 C++ CLI with no Rust bindings and is disqualified for a distributed app regardless. The algorithm is fifteen lines — write it.

Bar height is amplitude; bar colour is the speaker. The hue comes from whichever turn's startMs/endMs covers that moment — the same derived-from-clusterId colours as the gutter markers — and the gaps between turns render short and dimmed. That second layer is the part worth having: amplitude alone tells you where the sound is, which you can hear anyway, while the colour tells you who held the floor and where the conversation changed hands. It is also the one piece of coarse navigation (P12) this direction allows itself, because it costs no vertical space and lives in chrome that already existed.

Colour is never the only encoding here: the bars are backed by a real <input type="range"> with an aria-valuetext of "1:14 of 4:02", so the scrubber is fully keyboard-operable and announces position without reference to hue. The speaker identity it encodes is also always available as text in the gutter beside the prose.

What this is not: not a per-word marker track, not a spectrogram, not a talk-time chart, and not a second timeline you can annotate. It is the existing scrub bar, told the truth about what is inside it.
